# HOT Imagery Dashboard

An interactive dashboard visualizing satellite imagery usage across humanitarian mapping tools.

**Live Dashboard:** [https://cgiovando.github.io/hot-imagery-stats/](https://cgiovando.github.io/hot-imagery-stats/)

## About

Humanitarian mapping efforts rely on satellite imagery from multiple providers including Microsoft Bing, Esri, Mapbox, and Maxar. This dashboard provides visibility into which imagery sources are used across the HOT Tasking Manager, MapSwipe and fAIr, helping the community understand imagery consumption patterns and plan for the future.

### What It Shows

- **Project counts and area** by imagery source (Bing, Esri, Mapbox, Maxar, OpenAerialMap by platform, etc.)
- **Area by imagery source per year**, and project counts over time (yearly or monthly)
- **Geographic distribution** of mapping projects worldwide (circles for TM, diamonds for MapSwipe, triangles for fAIr)
- **Country-level breakdown** of mapping activity, by imagery source
- **CSV download** of the currently filtered projects
- **Cascading filters** - selecting one filter narrows options in all others (tool, year, imagery, country, organization, status)
- **Shareable URLs** - filter state and map position are synced to the URL for easy sharing
- **Auto-zoom** - map fits to the extent of filtered data

## Data Sources

### Tasking Manager (live)

Project data is sourced from the [HOT Tasking Manager API](https://tasking-manager-tm4-production-api.hotosm.org/api/v2/) via [insta-tm](https://github.com/cgiovando/insta-tm), a daily ETL pipeline that mirrors project metadata to Cloudflare R2.

### MapSwipe (live)

Project data is sourced from the [MapSwipe](https://mapswipe.org) public data exports and GraphQL API. Imagery provider information comes from the API for recent projects and a legacy database export for older projects. Countries are derived from project centroids.

### fAIr (live)

[fAIr](https://fair.hotosm.org) is HOT's AI-assisted mapping tool. Datasets come from the public fAIr API, with area computed from their training AOIs. OpenAerialMap imagery is classified by platform (drone, satellite, aircraft) using the [oam-api](https://github.com/cgiovando/oam-api) catalog.

### Excluded projects

By default the dashboard leaves out projects that never had any mapping activity (Tasking Manager: 0% mapped, no mappers and no time logged; MapSwipe: 0% progress and no contributors) and projects over 1M km², which are world- or country-scale outlines rather than mapped areas. Each record carries `excluded` and `excludedReason` fields, and a checkbox brings them back into every view. Tasking Manager can report 0% mapped for projects that were worked on, so mapper activity, not the percentage, decides exclusion.

## Tech Stack

- **Vanilla HTML/JS** - No build step, served as a static site
- [Tailwind CSS](https://tailwindcss.com/) - Styling via CDN
- [MapLibre GL JS](https://maplibre.org/) - Interactive map rendering
- [Chart.js](https://www.chartjs.org/) - Data visualizations
- [insta-tm](https://github.com/cgiovando/insta-tm) - TM data pipeline
- Python scripts for MapSwipe data fetching and summary generation

## Getting Started

### View the Dashboard

Visit **[https://cgiovando.github.io/hot-imagery-stats/](https://cgiovando.github.io/hot-imagery-stats/)** - no installation required.

### Local Development

```bash
# Clone the repository
git clone https://github.com/cgiovando/hot-imagery-stats.git
cd hot-imagery-stats

# Download the current data (generated by CI, not stored in git)
for f in projects_summary mapswipe_summary fair_summary oam_platform_cache; do
  curl -fsSL -o docs/$f.json https://cgiovando.github.io/hot-imagery-stats/$f.json
done

# Serve locally
python3 -m http.server 8000 -d docs
```

Then open `http://localhost:8000`

### Fetch Fresh Data

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Fetch MapSwipe and fAIr data
python scripts/fetch_mapswipe.py
python scripts/fetch_fair.py

# Generate unified summary (TM data from the insta-tm R2 bucket)
export S3_ENDPOINT_URL=...  AWS_ACCESS_KEY_ID=...  AWS_SECRET_ACCESS_KEY=...
python scripts/generate_summary.py
```

Each script refuses to overwrite its output if a source suddenly returns far fewer records than the previous run; pass `--force` when that drop is expected.

## Deployment

The dashboard is published to GitHub Pages by a [GitHub Action](.github/workflows/update-data.yml) (Pages source: GitHub Actions). It runs daily, on every push to `main`, and on demand. Each run downloads the previously published data files, fetches MapSwipe and fAIr data, updates the unified `projects_summary.json` incrementally from the insta-tm R2 bucket, and deploys `docs/` with the fresh data. Data files are never committed, so the repository holds code only.

The workflow needs the `S3_ENDPOINT_URL`, `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` repository secrets. It fails (after deploying) if any source has not updated for more than 48 hours.
